1.2 Tipos de Datos Abstractos (TDA)

Un Tipo de Dato Abstracto (TDA) es un modelo matemático que define un conjunto de valores y un conjunto de operaciones que se pueden realizar sobre esos valores, sin especificar cómo se implementan internamente.

El TDA separa la interfaz (qué se puede hacer) de la implementación (cómo se hace). Esto permite cambiar la representación interna sin afectar el código que usa el TDA.

A Componentes de un TDA

📦

Datos / Estado

La información que almacena el TDA (elementos, tamaño, capacidad, etc.).

⚙️

Operaciones

Funciones o métodos que manipulan el estado: crear, insertar, eliminar, consultar…

🔒

Encapsulamiento

La representación interna está oculta; solo se accede a través de la interfaz pública.

B Interfaz vs Implementación

Interfaz (contrato)

  • Define qué operaciones existen
  • Especifica precondiciones y postcondiciones
  • Es lo que ve el usuario del TDA
  • Ejemplo: push(x), pop(), top(), isEmpty()

Implementación

  • Define cómo se almacenan los datos
  • Puede usar arreglos, listas, nodos, etc.
  • Puede cambiarse sin romper el código cliente
  • Ejemplo: pila con arreglo estático o con lista enlazada
🔑 Principio clave “Programar contra la interfaz, no contra la implementación”. Esto es la base del diseño modular y de la programación orientada a objetos aplicada a estructuras de datos.

C Modularidad y POO

En la programación orientada a objetos, un TDA se implementa típicamente como una clase:

  • Los atributos privados representan el estado interno.
  • Los métodos públicos forman la interfaz del TDA.
  • El constructor inicializa el TDA.

Ejemplo conceptual de un TDA Pila en pseudocódigo: 

TDA Pila<T>
  // Operaciones
  crear()          → Pila vacía
  push(elemento)   → inserta en el tope
  pop()            → elimina y devuelve el tope
  top()            → consulta el tope sin eliminar
  isEmpty()        → verdadero si no hay elementos
  size()           → número de elementos

1.3 Ejemplos de TDA's

📚 TDA Pila (Stack)

Disciplina: LIFO (Last In, First Out) — el último en entrar es el primero en salir.

OperaciónDescripciónComplejidad típica
push(x)Inserta x en el topeO(1)
pop()Elimina y retorna el topeO(1)
top() / peek()Consulta el topeO(1)
isEmpty()¿Está vacía?O(1)

Aplicaciones

  • Evaluación de expresiones aritméticas
  • Llamadas a funciones (pila de ejecución)
  • Deshacer / rehacer (undo-redo)
  • Navegación web (historial atrás)
  • Recorrido DFS en grafos y árboles

🚶 TDA Cola (Queue)

Disciplina: FIFO (First In, First Out) — el primero en entrar es el primero en salir.

OperaciónDescripciónComplejidad típica
enqueue(x)Inserta x al finalO(1)
dequeue()Elimina y retorna el frenteO(1)
front()Consulta el frenteO(1)
isEmpty()¿Está vacía?O(1)

Variantes

  • Cola circular: reutiliza el espacio del arreglo
  • Bicola (deque): inserción/eliminación en ambos extremos
  • Cola de prioridad: el elemento de mayor prioridad sale primero

Aplicaciones

  • Colas de impresión / atención de clientes
  • Planificación de procesos (CPU scheduling)
  • BFS en grafos
  • Buffers de E/S

🔗 TDA Lista

Colección ordenada de elementos donde cada uno tiene una posición. Puede implementarse con arreglos o nodos enlazados.

Inserción al inicioAgregar al principioO(n)O(1)
Inserción al finalAgregar al finalO(1)*O(1)**
BúsquedaEncontrar un valorO(n)O(n)

Más TDA comunes

🗂️ Conjunto (Set)

  • Colección sin elementos duplicados
  • Operaciones: add, remove, contains, union, intersection

🗺️ Mapa / Diccionario (Map)

  • Asocia claves con valores
  • Operaciones: put, get, remove, containsKey

🌳 Árbol (Tree)

  • Estructura jerárquica con raíz y nodos hijos
  • Operaciones: insert, delete, search, traversals

📊 Grafo (Graph)

  • Conjunto de vértices y aristas
  • Operaciones: addVertex, addEdge, neighbors, path

D Ejemplo: TDA Pila en Python

class Pila:
    """TDA Pila implementado con lista de Python (arreglo dinámico)."""

    def __init__(self):
        self._datos = []          # representación interna (oculta)

    def push(self, elemento):
        """Inserta un elemento en el tope."""
        self._datos.append(elemento)

    def pop(self):
        """Elimina y retorna el elemento del tope."""
        if self.is_empty():
            raise IndexError("Pila vacía")
        return self._datos.pop()

    def top(self):
        """Retorna el elemento del tope sin eliminarlo."""
        if self.is_empty():
            raise IndexError("Pila vacía")
        return self._datos[-1]

    def is_empty(self):
        return len(self._datos) == 0

    def size(self):
        return len(self._datos)

# Uso
p = Pila()
p.push(10)
p.push(20)
print(p.top())   # 20
print(p.pop())   # 20
print(p.size())  # 1
Observa El usuario de la clase Pila no necesita saber que internamente se usa una lista. Podríamos cambiar la implementación a una lista enlazada y el código cliente seguiría funcionando igual.
