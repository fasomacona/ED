1.5 Análisis de algoritmos

El análisis de algoritmos permite predecir y comparar el comportamiento de distintos algoritmos que resuelven el mismo problema, independientemente del hardware o del lenguaje. Nos interesa medir principalmente:

  • Complejidad en el tiempo: cuántas operaciones elementales realiza.
  • Complejidad en el espacio: cuánta memoria adicional utiliza.

A Notación asintótica (Big-O)

La notación Big-O describe el orden de crecimiento de una función cuando el tamaño de la entrada (n) tiende a infinito. Nos da una cota superior del tiempo (o espacio) en el peor caso.

Órdenes más comunes (de mejor a peor)

Notación Nombre Ejemplo n = 10 n = 1 000 n = 1 000 000
O(1) Constante Acceso a arreglo por índice 1 1 1
O(log n) Logarítmica Búsqueda binaria ~3 ~10 ~20
O(n) Lineal Recorrer una lista 10 1 000 1 000 000
O(n log n) Lineal-logarítmica Merge sort, Heap sort ~33 ~10 000 ~20 000 000
O(n²) Cuadrática Burbuja, selección, inserción 100 1 000 000 10¹²
O(2ⁿ) Exponencial Fuerza bruta (subconjuntos) 1 024 ~10³⁰¹ inmenso
📌 Regla práctica Para entradas grandes: preferir O(1) y O(log n); aceptar O(n) y O(n log n); evitar O(n²) y peores cuando n es grande.

1.5.1 Complejidad en el tiempo

Se mide el número de operaciones elementales (comparaciones, asignaciones, operaciones aritméticas) en función del tamaño de la entrada n.

Casos de análisis

  • Mejor caso (Ω): el escenario más favorable (ej. elemento buscado está al inicio).
  • Caso promedio (Θ): comportamiento esperado sobre todas las entradas posibles.
  • Peor caso (O): el escenario más desfavorable (el más usado en la práctica).

Ejemplo: búsqueda lineal

def busqueda_lineal(lista, objetivo):
    for i in range(len(lista)):      # se ejecuta hasta n veces
        if lista[i] == objetivo:     # comparación
            return i
    return -1
  • Mejor caso: elemento en la primera posición → O(1)
  • Peor caso: elemento al final o no existe → O(n)
  • Caso promedio: ≈ n/2 comparaciones → O(n)

Ejemplo: búsqueda binaria (requiere lista ordenada)

def busqueda_binaria(lista, objetivo):
    izq, der = 0, len(lista) - 1
    while izq <= der:
        medio = (izq + der) // 2
        if lista[medio] == objetivo:
            return medio
        elif lista[medio] < objetivo:
            izq = medio + 1
        else:
            der = medio - 1
    return -1

En cada paso se reduce a la mitad el intervalo → O(log n) en el peor caso.

1.5.2 Complejidad en el espacio

Mide la cantidad de memoria adicional que necesita el algoritmo (además de la entrada). También se expresa con notación Big-O.

Algoritmo / EstructuraEspacio auxiliarNotas
Búsqueda lineal / binaria O(1) Solo variables escalares
Merge sort O(n) Necesita arreglo auxiliar
Quick sort (promedio) O(log n) Profundidad de recursión
Lista enlazada (n nodos) O(n) Un nodo por elemento + punteros
Matriz de adyacencia (grafo) O(V²) V = número de vértices
⚠️ Trade-off tiempo–espacio A menudo se puede mejorar el tiempo usando más memoria (tablas hash, memoización) o reducir memoria sacrificando velocidad. El análisis ayuda a elegir el equilibrio adecuado.

1.5.3 Eficiencia de los algoritmos

Un algoritmo es eficiente si utiliza de forma óptima (o aceptable) los recursos de tiempo y memoria para el tamaño de problema esperado.

Cómo comparar dos algoritmos

  1. Determinar la complejidad temporal y espacial de cada uno (Big-O).
  2. Considerar el tamaño típico de las entradas en el problema real.
  3. Si las complejidades son similares, medir tiempos reales (benchmarking).
  4. Valorar también legibilidad, facilidad de implementación y mantenibilidad.

Ejemplo práctico: dos formas de sumar los elementos de una lista

# Algoritmo A – iterativo  → O(n) tiempo, O(1) espacio
def suma_iterativa(lista):
    total = 0
    for x in lista:
        total += x
    return total

# Algoritmo B – recursivo  → O(n) tiempo, O(n) espacio (pila de llamadas)
def suma_recursiva(lista):
    if not lista:
        return 0
    return lista[0] + suma_recursiva(lista[1:])

Ambos son O(n) en tiempo, pero el recursivo usa O(n) de espacio en la pila de llamadas y puede provocar desbordamiento de pila con listas muy grandes. Por tanto, el iterativo es más eficiente en espacio.

B Reglas prácticas para calcular Big-O

  1. Secuencia: se suma (se toma el término dominante).
    O(f) + O(g) = O(max(f, g))
  2. Anidamiento (bucles anidados): se multiplica.
    for i in range(n): for j in range(n): ... → O(n²)
  3. Constantes: se ignoran.
    O(3n + 5) = O(n)
  4. Términos de menor orden: se eliminan.
    O(n² + n log n + n) = O(n²)
